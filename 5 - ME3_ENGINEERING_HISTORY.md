## 1. Establishing the real Pi voice path

The project developed a Pipecat pipeline around continuous capture, local VAD/AEC and student-built ASR/TTS MCP services. Keeping MCP processes on the Pi did not mean all inference was local: the selected normal ASR ultimately used Groq `whisper-large-v3-turbo`, while Piper synthesis ran on the Pi. That distinction matters for latency, credentials, resource use and outage behavior.

Capture, synthesis and playback were treated as separate stages. Producing PCM was not assumed to mean a listener heard the whole reply. Generation ownership, callback-buffer behavior and cancellation tests were needed because stale audio could otherwise arrive after a newer user turn. Later pacing and cancellation repairs remained within this voice architecture rather than replacing it with an unrelated speech-to-speech service.

## 2. Moving from restricted demonstrations to the original Onit planner

The intended assistant had to interpret freely expressed goals through actual tool schemas. The selected design therefore used the original native Onit task loop as the sole general-purpose planner, with a host broker controlling tool dispatch. A fixed phrase router or a fallback workflow was not accepted as evidence of general task understanding.

The host retained source/native identities, permissions, current-generation checks, bounded IPC and operation journals. Tool results were treated as evidence, not authorization. Native task working memory was explicitly distinguished from saved user notes. The final main reasoning selection is the existing account-backed `gpt-6.1-sol` transport; historical Google/Groq model constants and test profiles do not identify the active ordinary planner.

Several provider candidates stopped on availability, protocol, quality or timing failures. Those attempts and charges were retained. For example, the earlier Gemini judge-readiness attempt received HTTP 503; that was one observed failure, not permanent account unavailability or permission for an automatic fallback. A later separately authorized readiness attempt must have a new bounded claim and preserve the old record.

## 3. Making coding and application outcomes inspectable

Early software goals exposed mismatches between natural model use and a deliberately bounded workspace: file versus directory test targets, pre-execution parameter errors, small write frames and test-resource/output limits. Corrections widened only the reviewed operation contract. Distinct structured no-effect rejections let Onit correct invalid arguments without disguising storage, identity, isolation or uncertain-execution failures as harmless feedback.

The workspace gained source-bound file versions, meaningful test receipts, owned service identities, offline dependency environments and artifact delivery. File/ZIP download and sandboxed HTML preview made outputs usable through the Pi GUI. Private namespace services were not silently exposed as arbitrary host browser ports.

Finite repair and multi-file application checks demonstrated software outcomes at their recorded revisions. The vault application later passed 11 independently checked tests, but that did not prove owner GUI acceptance, universal coding success or production-security assurance. Optional durable recovery and background execution remained separate qualification scopes rather than assumptions derived from persisted files.

## 5. Qualifying interruption and ownership rather than duration alone

Overlap work found concrete lifecycle races: an ASR result could be lost during a provisional onset, a consumed warm worker might not be replaced for a fresh capture, and a strict worker TTL could leave a readiness gap. Repairs were tested with exact owner/generation/token/source/pending-review fences and bounded cleanup.

Semantic candidates were also measured independently. Slow remote floor decisions and a local NLI candidate's inability to satisfy its frozen development constraints were retained as failures, not tuned into a success on the same examples. The selected optional warm floor lane later used the existing Qwen role through a tool-free native Onit path. It was advisory: it could not execute effects, confirm a pending review or replace the ordinary GPT planner.

The accepted software/owner cases do not establish acoustic speaker identity or directedness under all backgrounds. A cancellation deadline with verified cleanup could become an explicit nonexecuting clarification; unknown failures and unverified cleanup still failed closed. No uncertainty was converted into automatic acceptance of an overlapping command.
